`www-client/zen` is derived from Gentoo's `www-client/firefox` ebuild. It uses upstream's `zen.source.tar.zst` release asset: a pre-imported Firefox tree with Zen patches, branding and l10n, with no top-level dir, so the ebuild extracts it into `${S}` itself. Branding uses `--with-app-name=zen --with-branding=browser/branding/release`. The Gentoo firefox patchset matching the Firefox base version (surfer.json `version.version`, e.g. 157.0.1 -> firefox-157-patches) applies cleanly; update FIREFOX_PATCHSET on version bumps to match the new Firefox base.

The source tarball has no `.hg`/`.git` or sourcestamp. When MOZ_SOURCE_REPO is set, `build/variables.py` fails with "could not resolve changeset; try setting MOZ_SOURCE_CHANGESET". Fix this in the ebuild's src_configure with `export MOZ_SOURCE_CHANGESET=${PV}`, since GitHub resolves the tag name in /commit/ URLs.

`www-client/zen-bin` installs `zen.linux-{x86_64,aarch64}.tar.xz` into /opt/zen.
